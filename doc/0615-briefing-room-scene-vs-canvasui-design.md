# 0615 - 브리핑룸: 별도 씬 vs CanvasUI 오버레이 설계 질문

## 질문
미션 시작 전 브리핑룸을 만들려고 함. 두 가지 안 중 선택 필요:
1. 씬을 하나 따로 두고 미션 텍스트 등을 출력하는 재사용 씬으로 만들기
2. CanvasUI를 만들어 각 미션 씬에 배치하고 텍스트/이미지를 출력. 이 경우 각 씬의 게임 조작, 사운드, 게임시간을 정지시키고 브리핑룸이 따로 보이도록 처리 필요

## 조사
- `Assets/Scripts/UI/MissionSelectManager.cs`: 미션 선택 시 `SceneManager.LoadScene(entry.sceneName)`로 각 미션 씬(Mission0~5, Sub_Mission1~4)을 직접 로드하는 구조. 씬 전환이 이미 표준 패턴.
- 별도 GameManager나 persistent scene(DontDestroyOnLoad 등)으로 여러 씬을 겹쳐 관리하는 구조는 확인 안 됨 - 씬 단위로 완전히 갈아끼우는 방식.

## 답변 (권장: 별도 씬 방식)
- 정지 로직이 필요 없어짐: 브리핑을 별도 씬으로 분리하면 미션 씬 자체가 로드되지 않은 상태이므로 조작/사운드/게임시간을 따로 멈추고 복원할 코드가 필요 없음. CanvasUI 오버레이 방식은 Time.timeScale, 오디오, 입력, 유닛 AI/코루틴까지 모두 멈추는 로직을 만들어야 해서 버그 표면이 큼.
- 기존 패턴과 일치: `MissionSelectManager.LoadMission()`이 이미 `SceneManager.LoadScene`으로 씬을 전환하는 구조이므로, 미션 선택 → 브리핑 씬(대상 미션 번호를 static 변수나 PlayerPrefs로 전달) → "시작" 버튼 → 실제 미션 씬 로드로 자연스럽게 확장 가능.
- 재사용성: 씬 하나 + 미션별 텍스트/이미지 데이터 매핑만 있으면 되고, 브리핑 UI 수정 시 모든 미션 씬을 다시 열 필요 없음.
- CanvasUI 오버레이가 유리한 유일한 경우는 "브리핑 중 미션 배경이 비쳐 보여야 한다"는 연출 요구가 있을 때뿐.

## 추가 논의 - 흐름 비교
사용자가 두 흐름을 제시:
1. 미션 선택 → 브리핑 씬 → 각 미션으로 이동
2. 미션 선택 → 미션 씬 이동 → 브리핑룸 UI 출력 → 인게임

흐름 2는 미션 씬이 이미 로드된 상태에서 브리핑 UI를 얹는 것이라 CanvasUI 오버레이 방식과 동일하게 정지 로직(스폰/AI/사운드를 브리핑 종료 전까지 막는 처리)이 필요함. 로딩 화면을 겸하려는 의도가 아니라면 흐름 1이 정지 로직 없이 더 단순하다고 안내.

## 결정
사용자가 흐름 1(브리핑 씬 하나를 두고 미션 선택에 맞춰 텍스트/이미지를 다르게 출력)로 확정. 브리핑룸 구성(씬 레이아웃/UI)은 사용자가 직접 진행 중이며, 완료되면 연결 작업(미션별 데이터 전달, "시작" 버튼→미션 씬 로드 배선) 지시 예정.

## 상태
설계 방향 확정, 코드 변경 없음. 사용자의 구성 완료 및 추가 지시 대기 중.
