# 0611 - 적 유닛이 플레이어 건물을 공격 안 하는 것처럼 보이는 문제 조사

## 최초 질문
"적 스포어브루드 별동대 애들이 공격을 오는데 플레이어 건물은 공격을 못하는거 같아 확인좀 해줘"

## 1차 조사 (오해 - 폐기)
처음엔 "플레이어 건물이 반격을 못 한다"는 뜻으로 이해하고 조사함:
- `BuildingController.cs`(플레이어 건물)엔 공격 로직이 전혀 없음(`AttackRange`/`TurretController`
  미참조) - 생산/랠리/리프트/사망 처리만 있음.
- 플레이어 건물 목록(`ko.json`의 `building.nta.*`)도 방어 타워 없이 생산 건물 6종뿐.

→ 사용자가 정정: 실제 의도는 "적(스포어브루드)이 플레이어 건물을 안 때린다"는 뜻이었음.

## 2차 조사 - 두 가지 적 AI 시스템 확인
`EnemyAIDirector.cs`에 서로 다른 두 시스템이 있음을 확인:
1. **웨이브(`AttackWaveRoutine`)**: `PickAttackTarget()`이 플레이어 "MainBase" 태그 건물(또는 아무
   건물)을 목표로 삼아 실제로 건물을 공격하러 감.
2. **별동대(`RaidRoutine`)**: `PickRaidTarget()`이 `CaptureSystem`(점령지)만 목표로 삼음 - 플레이어
   건물은 애초에 후보에 안 들어감(설계상 정상).

Sub_Mission4 씬엔 둘 다 설정돼 있어서 어느 쪽을 보고 있는지 사용자에게 재확인함.

## 3차 조사 - 근접 유닛(립팽)만 공격을 안 함
사용자 확인: "립팽(근접유닛)은 건물을 공격 못 하는 것 같은데, 스피터(원거리)는 건물을 잘 공격함."
→ 립팽 `UnitRange=4`, 스피터 `UnitRange=13` (`EnemyAttackRange.UnitRange`). 둘 다 `NavMeshAgent`
설정(radius 0.5, stoppingDistance 1)은 동일. 건물 쪽 `NavMeshObstacle`(Box, extents
{0.35, 0.5, 0.2} × localScale {6,4,6})도 동일 - 정적 분석만으로는 사거리 차이 외의 원인을 못 찾음.

Unity 에디터가 실행 중이라 `uloop` 툴로 씬에 배치된 Ripfang 인스턴스를 직접 조회:
- 해당 인스턴스는 건물에서 88~98유닛 떨어져 있고 `NavMeshAgent.isOnNavMesh = False` 상태였음 -
  다만 이건 씬에 미리 놓인 테스트용 개체라 실제 웨이브 스폰 상황과 무관한 것으로 판단.

사용자가 직접 재확인: "건물 바로 앞/옆에서 멈춰서 서 있음(공격 안 함)." → 사거리 문제가 아니라
도착은 했는데 공격을 안 거는 상태로 판단, 재현 스크립트를 준비함(SupplyDepot을 립팽 근처로
순간이동시키고 `AttackMoveTo` 강제 호출 + 상태 리플렉션 덤프).

## 최종 결론
사용자가 직접 플레이 확인한 결과 **정상 동작으로 판명**:
- 처음엔 "공격을 안 한다"고 느꼈으나, 재확인해보니 실제로는 공격을 하고 있었음.
- "땅속에 박혀서 그런가" 의심도 있었으나 이후 관찰에서 기각.
- 최종 판단: 건물에 붙어 있는 동안 근처에 플레이어 유닛이 나타나면 `EnemyAttackRange`가 매 프레임
  가장 가까운 유효 대상을 다시 선택하므로(`GetEngagedOrClosestTarget`/`GetClosestTarget`) 건물 대신
  그 유닛을 우선 교전 대상으로 삼는 것으로 보임 - 기존 설계상 정상 동작이고, 버그 아님.

**상태: 사용자 요청으로 조사 종료 지시.** (아래 추가 발견은 종료 지시 이후 백그라운드에서 이미 실행
중이던 진단 스크립트 결과 - 코드 변경 없음, 사용자에게 보고만 하고 별도 조치는 대기 중)

## 추가 발견 (백그라운드 재현 테스트, 종료 지시 이후 도착)

립팽을 보급고에서 정확히 2유닛 거리(사거리 4 이내)에 놓고 `currentState`를 강제로 `Idle`로 만든
통제된 재현에서, `EnemyAttackRange.targetsInRange`가 끝까지 비어 있었음 - `Physics.OverlapSphere`로는
콜라이더 겹침이 확인되는데도 `OnTriggerEnter`가 발생하지 않음.

원인으로 추정되는 조합:
- 립팽 `Rigidbody`가 non-kinematic인데 힘을 안 받아 ~0.3~0.4초 안에 sleep 상태로 들어감
  (`sleepThreshold=0.005`, `WakeUp()` 호출 후에도 금방 재취침 확인)
- `NavMeshAgent`가 `transform.position`을 직접 덮어써서 이동(물리 엔진 경유 X)
- `ProjectSettings/DynamicsManager.asset`의 `m_AutoSyncTransforms: 0`

→ "잠든 non-kinematic Rigidbody의 Transform을 외부에서 계속 덮어쓰면 트리거 이벤트가 안 터진다"는
Unity의 알려진 함정 패턴과 일치. 스피터가 멀쩡한 이유는 사거리(13+마진 5=18)가 넓어 스폰 직후(아직
안 잠들었을 때) 이미 타겟을 잡아두고, 이후엔 새 `OnTriggerEnter` 없이 기존 타겟과의 거리만 재기
때문으로 추정. 근접 유닛(사거리 4+마진 5=9)은 스폰 시점에 이미 사거리 안에 뭔가 있을 확률이 낮아서
"이동 중 새로 트리거 감지"에 의존하는데, 그게 이 조합 때문에 막히는 것으로 보임.

**간헐적 증상과의 정합성**: 사용자가 직접 재확인했을 때 "잘 공격하는 것 같다"고 관찰한 건, 우연히
리지드바디가 아직 안 잠든 타이밍(스폰 직후 등)이었을 가능성이 있음 - 이 원인이 맞다면 근접 유닛은
상황(스폰 후 경과 시간, 정지해 있던 시간 등)에 따라 공격 여부가 간헐적으로 갈릴 수 있음.

**제안 수정(미적용)**: 근접 유닛(립팽 등) 프리팹의 `Rigidbody`를 kinematic으로 전환 - 가장 스코프가
작은 수정. 다른 대안은 프로젝트 전역 `Physics.autoSyncTransforms` 활성화(영향 범위가 훨씬 큼).

사용자 확인 후 적용 여부 결정 예정.
