# 0593. 실루엣이 안 가려진 상태에서도 계속 보이는 버그 - 수정

**날짜:** 2026-08-16

## 요청 내용

> 그냥 화면에 보일떄는 실루엣이 보이면 안되고 건물 뒤나 언덕 뒤에 가려진 부분에만 실루엣
> 보이도록해줘
>
> (후속) 만약 이미 그렇게 한거라면 유닛 자기 자신이 자기를 가렸다고 생각하는건지 확인해줘

## 원인

doc/0592에서 만든 `UnitSilhouette` 셰이더는 `ZTest Greater`로 "지금 이 픽셀에 이미 더 가까운 뭔가가
그려져 있을 때만" 그리는 방식이다. 안 가려진 부분에서는 깊이버퍼에 이미 유닛 자기 자신의 원래
표면 깊이가 기록돼 있으므로, 이론적으로는 실루엣 패스도 같은 위치에서 같은 깊이가 나와야 해서
"더 뒤"가 아니라 "같음" → 그려지지 않아야 정상이다.

문제는 원래 표면 패스와 실루엣 패스가 서로 다른 셰이더 프로그램으로 컴파일되면서, 완전히 동일한
버텍스 변환이라도 부동소수점 연산 순서가 미묘하게 달라져 극히 작은 오차가 생길 수 있다는 점이다.
이 오차가 우연히 "실루엣 쪽이 아주 조금 더 뒤"로 계산되면, 유닛이 자기 자신에게 가려졌다고
오판(self-occlusion)해서 안 가려진 상태에서도 실루엣이 계속 보여버린다.

## 수정

`Assets/Shader/UnitSilhouette.shader`의 Silhouette 패스에 작은 깊이 오프셋(`Offset -1, -1`)을 추가해,
이 패스의 깊이가 항상 원래 표면보다 확실히 더 가깝게(작게) 계산되도록 강제로 밀어넣는다.

```diff
             Cull Back
             ZWrite Off
             ZTest Greater
+            // 안 가려진 부분에서는 원래 표면과 이 패스의 깊이가 이론상 같아야 하지만, 서로 다른
+            // 셰이더 프로그램이라 부동소수점 오차로 아주 미세하게 어긋날 수 있다 - 그 오차가 우연히
+            // "더 뒤"로 계산되면 자기 자신에게 가려졌다고 오판해 안 가려진 상태에서도 계속 보여버린다.
+            // 이 패스의 깊이를 살짝 당겨서(더 가깝게) 그 오차를 흡수한다 - 언덕/건물과의 실제 거리
+            // 차이는 훨씬 크므로 진짜 가려짐 판정에는 영향이 없다.
+            Offset -1, -1
             Blend One Zero
```

- 안 가려진 부분: 실루엣 깊이(살짝 당겨짐) < 원래 표면 깊이 → 확실히 "더 뒤"가 아님 → 안 그려짐
- 언덕/건물에 가려진 부분: 그 차이가 언덕과의 실제 거리 차보다 훨씬 작아서 여전히 "더 뒤"로 정상
  판정 → 그대로 보임

## 검증

`Shader.Find("Custom/UnitSilhouette")` 정상(컴파일 에러 없음). Play Mode 스크린샷으로, 언덕/건물에
가려지지 않고 훤히 보이는 유닛들(트루퍼/터렛/베이스)이 더 이상 자기 몸에 초록 실루엣이 새어나오지
않고 정상 색상으로만 렌더링되는 것을 확인함. (실제 언덕/건물 뒤에 가려졌을 때도 여전히 잘 보이는지는
이번엔 직접 씬을 세팅해서 확인하지 않았음 - 오프셋 값이 실제 지형 간 거리차보다 훨씬 작아 로직상
영향 없어야 하지만, 게임에서 한 번 눈으로 확인해보면 좋음.)
