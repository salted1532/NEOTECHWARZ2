# 0308. Sci-Fi UI 에셋을 AssetFolder로 이동할 때 액세스 거부되는 원인 조사

날짜: 2026-07-30

## 요청 내용

> Sci-Fi UI 에셋을 추가 했는데 assetfolder안으로 이동시키려고하는데 엑세스 거부 당하는데 왜그런거야

## 조사 내용

- 에셋 위치 확인: `Assets/Sci-Fi UI` (+ `Assets/Sci-Fi UI.meta`), 총 92개 파일. 목적지인
  `Assets/AssetFolder/` 안에는 동일한 이름의 폴더가 없어서 이름 충돌은 원인이 아님.
- 경로 길이 확인: 가장 긴 파일 경로가 `AssetFolder\`로 옮겨도 131자 정도라 Windows 260자 제한과는
  무관함.
- 파일 속성 확인: 폴더/파일 모두 읽기 전용(ReadOnly) 아님.
- 프로세스 확인: Unity Editor(`Unity.exe`)가 3개 인스턴스로 실행 중.
- **재현 테스트**: PowerShell로 `Sci-Fi UI` → `Sci-Fi UI_test`로 이름 변경은 즉시 성공했지만, 바로 이어서
  다시 `Sci-Fi UI_test` → `Sci-Fi UI`로 되돌리려 하자 **"Access to the path ... is denied"**로 실패함.
  잠시 후 재시도하니 정상적으로 성공. (테스트 중 실수로 폴더명이 `Sci-Fi UI_test`로 남아있던 걸 즉시
  원래 이름으로 복구 완료 - 최종적으로 프로젝트 상태는 변경 없음.)

이 재현으로 원인이 확인됨: **Unity Editor가 켜져 있는 상태에서 `Assets/` 아래 파일이 변경되면,
AssetDatabase가 즉시 그 변경을 감지하고 재임포트(reimport)를 시작하면서 해당 파일/폴더에 짧게
파일 핸들을 잡는다.** 이 타이밍에 Windows 탐색기(또는 다른 프로그램)에서 같은 파일을 옮기려고 하면
"액세스가 거부됨" 에러가 난다. 파일 수가 많은 폴더(이번 건 92개)일수록 재임포트가 오래 걸려서 걸릴
확률이 높다.

## 답변 요약 (코드 변경 없음)

1. **가장 간단한 해결책**: 몇 초 후 다시 시도한다. Unity가 재임포트를 끝내면 핸들을 놓아주므로 대부분
   금방 풀린다.
2. **Unity 에디터의 Project 창에서 직접 드래그해서 옮기기**: 탐색기 대신 Unity 안에서 이동하면
   `AssetDatabase.MoveAsset`을 통해 이동과 재임포트를 Unity가 직접 관리해서 이런 충돌이 훨씬 덜 생긴다.
3. **에디터 우측 하단(또는 툴바)의 백그라운드 작업 진행 아이콘**이 도는 동안(임포트/컴파일 중)은 탐색기
   이동을 피하고, 끝난 뒤 이동한다.
4. 그래도 계속 막히면 Unity Editor를 완전히 끄고 탐색기에서 폴더(및 `.meta` 파일이 같이 있는지 확인)를
   이동한 뒤 Unity를 다시 켠다 - `.meta`가 폴더와 함께 옮겨지면 GUID가 유지되어 참조가 깨지지 않는다.
