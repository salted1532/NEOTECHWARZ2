# 0594. 실루엣이 유닛 자기 자신의 다른 부품에 가려서 오작동하는 문제 - 제안

**날짜:** 2026-08-16

## 요청 내용

> 내가 uloop 스크린샷에다가 실루엣.png로 플레이 화면을 찍었는데 현재 건물 뒤나 언덕뒤로 가려진
> 부분에 대해선 잘 작동하는데 가려지지 않았을때도 초록색으로 부분부분 실루엣이 그대로 적용되어
> 보여서 이것좀 확인해주고 고쳐줘

사용자가 제공한 스크린샷(`실루엣.png`)에서 확인: 터렛이 달린 건물이 자기 몸 여기저기에 초록
얼룩으로 보임(`실루엣 꺼져야함`으로 표시) - 언덕/다른 건물에 가려진 게 아님.

## 원인 (doc/0593과는 다른 문제)

doc/0593에서 고친 "정밀도 오차로 자기 자신과 같은 위치에서 오판" 문제와 달리, 이번엔 **진짜로
존재하는 깊이 차이** 때문에 생기는 문제다: 터렛 달린 건물은 베이스 메쉬와 터렛 메쉬가 서로 다른
렌더러(자식 오브젝트)로 나뉘어 있고, 터렛이 베이스보다 카메라 쪽으로 실제로 몇 유닛 튀어나와 있다.
`UnitSilhouette.Apply()`는 이 모든 렌더러 각각에 실루엣 머티리얼을 붙이는데, 지금 셰이더는 화면
전체의 공유 깊이버퍼(모든 오브젝트가 다같이 쓰는)와 비교하기 때문에, 베이스 메쉬의 실루엣 패스가
"이 픽셀엔 이미 (자기 터렛이) 더 가까이 그려져 있네" → 진짜로 맞는 판정이라 자기 터렛에 가려진
부분에서도 정상적으로 "가려짐"으로 통과해버린다. 셰이더 입장에선 "언덕에 가려짐"과 "자기 부품에
가려짐"을 구분할 방법이 아예 없다 - 정보 자체가 없다.

## 해결 방향

지형(Ground)/건물(Building) **레이어만** 그린 별도의 "가림막 전용" 깊이 텍스처를 만들어서,
실루엣 셰이더가 화면 전체 깊이버퍼 대신 그 텍스처와만 비교하게 한다 - 그러면 유닛(자기 자신
포함)은 애초에 그 텍스처에 없으므로 자기 부품에 의한 오판이 구조적으로 불가능해진다.

프로젝트의 기존 레이어를 그대로 재사용(새 레이어 안 만듦, 라이브로 직접 확인함):
- Layer 7 "Ground" - 지형/언덕
- Layer 9 "Building" - 건물
- (Layer 6 "Unit"은 제외 - 유닛끼리는 서로 가려도 실루엣이 뜨면 안 됨)

## 변경 계획

### 1. 보조 카메라로 "가림막 전용" 깊이 텍스처 생성
`Assets/Scripts/Effects/UnitSilhouette.cs`의 정적 부트스트랩에 추가 - 프리팹/씬 수정 없이 첫
`Apply()` 호출 시 자동 생성:
- `Camera.main`의 자식으로 보조 카메라 생성(부모-자식 관계라 위치/회전은 매 프레임 자동으로
  따라감 - `CameraControl.cs` 확인 결과 줌은 위치 이동으로 구현되고 FOV는 안 바뀌므로, FOV/근평면/
  원평면은 설정 시점에 한 번만 복사하면 충분함).
- `cullingMask` = Ground | Building 레이어만.
- `targetTexture` = 화면 해상도와 동일한 크기의 깊이 전용 RenderTexture(`RenderTextureFormat.Depth`).
  화면 해상도가 바뀌면(창 크기 변경 등) 다시 생성.
- 매 프레임 렌더된 이 텍스처를 `Shader.SetGlobalTexture("_OccluderDepthTex", ...)`로 전역
  등록 - 모든 실루엣 머티리얼 인스턴스가 별도 배선 없이 바로 접근 가능.

### 2. `Assets/Shader/UnitSilhouette.shader` 수정
하드웨어 `ZTest Greater`(공유 깊이버퍼 비교) 대신, 프래그먼트 셰이더 안에서 직접
`_OccluderDepthTex`를 화면 UV로 샘플링해서 수동 비교한다.
- `ZTest Always`로 바꾸고(항상 실행은 되지만 안에서 직접 판단)
- 이 프래그먼트의 화면 UV를 계산 (`IN.positionCS.xy / _ScreenParams.xy`)
- `_OccluderDepthTex`에서 그 UV의 깊이를 샘플링
- 두 깊이 값을 `Linear01Depth()`(URP 제공, 플랫폼별 깊이 관례 차이를 흡수)로 정규화해서 비교 -
  내 프래그먼트가 가림막보다 더 멀면(가려짐) 그리고, 아니면(가려짐 없음) `clip(-1)`로 버림.
  같은 카메라 설정(위치/FOV/근원평면)을 공유하므로 `_ZBufferParams`를 그대로 재사용 가능.
- doc/0593의 `Offset -1, -1`은 더 이상 필요 없음(자기 자신과 비교하는 경우 자체가 없어짐) -
  제거.

## 남은 위험 요소
- 화면 해상도 변경(창 크기 조절, 풀스크린 토글) 시 RenderTexture 재생성 필요 - 매 프레임 크기
  체크 후 다를 때만 재생성(매 프레임 새로 만들지 않음).
- 보조 카메라가 매 프레임 씬을 한 번 더 그리므로 약간의 추가 렌더링 비용이 든다(다만 유닛 없이
  지형/건물만 그리므로 상대적으로 가벼움).
- 셰이더에서 수동 깊이 비교로 바뀌므로 실제 게임 화면으로 눈으로 확인(스크린샷)해서 검증 필요 -
  기존 자동 HW ZTest보다 직접 구현한 로직이라 첫 시도에 미세하게 어긋날 가능성 있음.
