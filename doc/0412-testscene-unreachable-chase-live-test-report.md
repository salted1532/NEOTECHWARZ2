# 0412 - TestScene 실측: 도달 불가 추격(0403~0411) 라이브 테스트 보고

**날짜:** 2026-08-04

**코드 변경 없음 - 조사/보고 전용.**

## 요청 내용

> 제대로 작동안해 너가 직접 testscene에서 테스트해보고 보고해줘 전체 코드를 좀 읽어도 좋을거 같아

`UnitController.cs`/`EnemyUnitController.cs`의 도달 불가 추격 로직([[0403]]~[[0411]])을 uloop로
TestScene에서 Play Mode로 직접 실행해서 검증하고 보고해달라는 요청.

## 테스트 방법

Play Mode에서 `execute-dynamic-code`로 리플렉션을 이용해:
1. 플레이어 유닛(`Assault Trooper`)의 `UnitController.AttackUnitTarget()`을 직접 호출해 적
   유닛(`Cyborg Soldier`)을 공격 명령.
2. 그 적 유닛을 완전히 도달 불가능한 위치(자신의 `NavMeshAgent`를 비활성화한 뒤 지상 100m
   상공으로 순간이동 - `NavMesh.CalculatePath`가 `CalculatePath-failed`를 반환하는, 완전히
   끊긴 지점)로 옮겨 강제로 "절대 도달 불가" 상태를 재현.
3. `Time.time`/필드 값(`chaseIsUnreachable`, `nextUnreachableRepathTime`,
   `lastMoveAgentToDestination` 등)을 리플렉션으로 주기적으로 읽고, 콘솔 로그([[0407]]의
   `[도달 불가 추격]` 디버그 로그)를 `get-logs`로 확인.

## 확인된 사실 1 - "여전히 도달 불가" 쿨다운이 코드상 1초보다 훨씬 자주 찍힘

`Time.time`을 기준으로(실제 벽시계 시간이 아니라 Unity 자체 게임 시간 기준) 깨끗한 구간을 하나
잡아 측정:

- 측정 시작 `Time.time = 343.1594`, 측정 종료 `Time.time = 364.7672` → 구간 22.51초(게임 시간)
- 그 사이 `[도달 불가 추격] 여전히 도달 불가...` 로그가 41회 발생 → 이벤트당 약 0.55초

코드에 있는 `UnreachableRepathInterval` 상수는 리플렉션으로 직접 읽어 `1`(1초)임을 확인했다.
즉 **코드가 의도한 1초 간격보다 대략 2배 더 자주** 재확인/재탐색 로그가 찍혔다. 이 결과는
반복 측정(수동으로 다른 구간에서도 비슷한 배율)에서도 일관됐다. 정확한 원인(왜 정확히 절반에
가까운 배율인지)은 이번 세션에서 확정하지 못했다 - `AttackOrderTick()`/`UpdateUnreachableChase()`
호출 경로 자체는 `Update()`당 한 번뿐임을 코드상 확인했으나, 실제 로그 빈도는 그와 맞지 않았다.

## 확인된 사실 2 - 콘솔에 수만 건의 Error가 쌓임 (원인 미확정)

테스트 도중 `clear-console`을 호출했을 때 두 차례에 걸쳐 각각 **44,648건**, **2,596건**의
Error 로그가 한꺼번에 지워진 것을 발견했다. **이 부분은 조사 과정의 실수다** - 무엇이 찍히고
있는지 스택트레이스를 먼저 확인했어야 했는데, 그 전에 `clear-console`을 먼저 호출해서 원본
에러 메시지를 잃어버렸다. 이후 같은 조건(적 유닛의 `NavMeshAgent`를 끄고 상공 100m로 순간이동)을
다시 재현해서 에러가 다시 쌓이는지, 어떤 메시지인지 잡으려 시도했지만:
- 주문 직후 몇 초 동안은 에러가 0건이었고,
- 수십 초 뒤에 다시 확인했을 때는 이미 수천 건이 쌓여있었지만 그 사이 정확히 언제/어떤
  메시지로 시작됐는지 잡지 못했다.

## 확인된 사실 3 - 테스트 중이던 플레이어 유닛이 알 수 없는 이유로 파괴됨

에러가 쌓이는 동안, 공격 명령을 내렸던 `Assault Trooper`(원본, 접미사 없는 개체)가 씬에서
완전히 사라졌다(`GameObject.Find`로 못 찾음, `AttackUnit` 태그 목록에도 없음 - 파괴됨).
사망 원인은 확인하지 못했다 - 도달 불가 상공에 떠 있는 채 이동도, 공격도 안 하는 대상에게
죽을 이유가 없는데도 사라졌다. 이 세션에서 같은 유닛에게 반복적으로(여러 번) 아주 먼 상공
좌표로 공격 명령을 재발급했었기 때문에, 그 반복된 원거리 이동/재탐색 과정에서 생긴 부작용일
가능성이 있지만 확정하지 못했다.

## 한계 - 이 테스트 방법 자체의 문제

이번 조사는 실제 "언덕 위 유닛" 상황이 아니라, **적 유닛의 `NavMeshAgent`를 강제로 끄고 지상
100m 상공으로 순간이동시키는 합성(synthetic) 방식**으로 "완전 도달 불가" 상태를 재현했다.
이건 코드가 실제로 다루도록 설계된 "경사로로 연결은 됐지만 끝까지 못 가는 언덕"(`PathPartial`)
과는 다른 케이스이고, `NavMeshAgent`를 코드 밖에서 직접 껐다 켰다 하는 것 자체가 Unity
NavMesh 시스템에 이례적인 상태를 유발했을 가능성이 있다. 즉 사실 1/2/3에서 관찰된 문제들이
**0403~0411 로직 자체의 버그**인지, **이번 테스트 방법이 만든 인위적 부작용**인지 이 세션
안에서 명확히 가르지 못했다.

## 권고

- 사실 1(쿨다운이 절반 간격으로 도는 것)은 재현성 있게 측정됐고 원인 후보를 좁히지 못했으므로,
  다음 세션에서 별도로 `Debug.Log`에 프레임 번호/카운터를 임시로 추가해 정확히 몇 프레임마다
  찍히는지부터 확인하는 게 좋겠다.
- 사실 2/3(에러 폭주, 유닛 원인불명 파괴)은 훨씬 심각해 보이지만, 이번 합성 테스트 방법의
  부작용일 가능성이 있어 **실제 지형(진짜 언덕)에서 재현되는지 먼저 확인**이 필요하다 -
  다음엔 `clear-console`을 절대 먼저 호출하지 않고 에러 스택트레이스부터 확보하겠다.
- 코드 변경은 하지 않았다(Play Mode를 Stop해서 이번 테스트로 만든 모든 상태는 원복됨).
