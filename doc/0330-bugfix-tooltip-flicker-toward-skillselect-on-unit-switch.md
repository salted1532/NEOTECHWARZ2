# 0330. 유닛 전환 시 스킬선택 쪽으로 툴팁 깜빡이는 버그 수정

**날짜:** 2026-07-31

## 요청

> 한 유닛 선택한 상태에서 다른 유닛 선택했을때 스킬선택 쪽으로 툴팁이 자꾸 깜박이는데 이것좀 확인하고
> 고쳐줘 마우스 위치 오류 인거 같기도 하고

## 원인

`Assets/Scripts/UI/ProductionSlot.cs`는 커맨드 패널/스킬 슬롯 등에서 재사용되는 풀링 방식 UI 슬롯
컴포넌트다. 호버 상태를 `isHovered` 필드로 들고 있고, 매 프레임 `Update()`에서 `isHovered`가 참이면
`RefreshTooltip()`을 호출해 툴팁을 계속 갱신한다.

문제는 `Clear()`(슬롯을 다른 커맨드로 재사용하기 전에 초기화하고 `SetActive(false)`하는 메서드)가
`isHovered`를 리셋하지 않았다는 것. Unity는 `GameObject.SetActive(false)`로 비활성화될 때
`OnPointerExit`을 호출하지 않으므로, 마우스가 버튼 위에 있는 상태에서 다른 유닛을 선택해 커맨드
패널이 통째로 재구성되면(기존 슬롯들이 `Clear()`된 뒤 새 데이터로 `SetData()` 재사용) 그 슬롯의
`isHovered`가 `true`로 남은 채 다음 데이터(예: 스킬선택 버튼)로 재활용됐다.

재활용된 슬롯이 `SetActive(true)`되는 즉시 `Update()`가 돌면서 `isHovered == true`이므로 실제
마우스가 그 위에 없는데도 `RefreshTooltip()`이 즉시 호출 → 엉뚱한(새) 데이터로 툴팁이 잘못된
위치(스킬선택 버튼 쪽)에 한 프레임 표시됨. 그 다음 프레임에 `TooltipUI.Update()`의 자체 안전장치
(`IsPointerOverTarget()` - 실제 마우스 좌표로 재검증)가 "마우스가 진짜 거기 없다"를 감지해 다시
`Hide()`함 → 이 표시↔숨김이 반복돼 "깜빡임"으로 보였음. 사용자가 짐작한 "마우스 위치 오류"는 결과적
증상은 맞지만, 실제 원인은 마우스 좌표 계산이 아니라 **재사용된 슬롯의 과거 호버 상태가 안 지워진
것**이었음.

## 수정

`ProductionSlot.Clear()`에 `isHovered`가 `true`였다면 리셋하고 `TooltipUI.Instance?.Hide()`를
직접 호출하는 코드 추가 — `OnPointerExit`이 못 불린 채 비활성화되는 경우를 `Clear()` 시점에 명시적으로
보충. 커맨드 패널/생산 대기열/스쿼드 패널/스킬 슬롯 등 `ProductionSlot`을 재사용하는 모든 곳에 공통
적용되는 근본 수정(호출부마다 따로 고칠 필요 없음).

`npx uloop-cli compile`로 에러 0개 확인.

## 결과

이제 유닛을 전환해 커맨드 패널이 재구성될 때, 마우스가 실제로 올라가 있지 않은 재활용 슬롯은 호버
상태가 함께 초기화되어 툴팁이 잘못된 위치에서 잠깐 나타났다 사라지는 깜빡임이 발생하지 않음.
